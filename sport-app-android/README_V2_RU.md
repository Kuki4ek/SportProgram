# Спортакус Android V2

Версия `2.0.1-light` — отдельная сборка приложения на Kotlin и Jetpack Compose. Она устанавливается рядом с предыдущей версией, использует единый светлый интерфейс и не предоставляет переключатель тёмной темы.

## Что изменено

- Принудительно используется светлая цветовая схема Material 3; переключатель тёмной темы отсутствует.
- Для основных CTA-кнопок используется отдельный зелёный `#79B505`; остальные элементы сохраняют прежний фирменный зелёный.
- Российский телефон форматируется прямо во время ввода: `+7 (999) 999-99-99`. Тот же формат передаётся в регистрацию, вход, восстановление пароля и редактирование профиля.
- После успешной регистрации и входа приложение запрашивает `GET /api/users/me` и заполняет профиль данными текущего пользователя.
- Статистика и график не подменяются демонстрационными числами: отсутствующие значения показываются как `0`, а при отсутствии истории активности отображается пустое состояние.
- Из редактирования профиля убраны местоположение и пароль. Доступны только личные поля, пришедшие из профиля, и их редактирование.
- История поиска хранит только фактически отправленные пользователем запросы; демонстрационные поисковые запросы удалены.
- В каталоге оставлено по одной примерной тренировке в каждой категории: «Кардио», «Сила», «Пилатес», «Восстановление». Каталог переведён на отдельный ключ настроек `local_exercise_catalog_v2_json`, чтобы не подхватывать старые демонстрационные записи.
- Панель «В процессе» появляется только после нажатия «Начать тренировку» и показывает прошедшее время. Её можно завершить.
- Нижняя панель действий на экране тренировки закреплена над системной панелью навигации.
- Сохранение профиля закрывает редактор только после успешного ответа сервера.

## Данные профиля и статистика

После регистрации/входа выполняется `GET /api/users/me` с заголовком `Authorization: Bearer <accessToken>`. Клиент распознаёт поля `login`, `email`, `phone`, `fullName`, `birthDate`, `height`, `weight`, `gender` и варианты названий статистики в camelCase/snake_case. Для SportCoins также читается `balance`.

Если сервер не возвращает количество тренировок, минут, избранного или историю активности, соответствующие показатели остаются нулевыми, а график не рисуется на выдуманных данных. Для появления реальной статистики эти поля должны быть включены в ответ backend API.

Сохранение редактируемого профиля сейчас отправляет `PUT /api/users/me` с полями личного профиля. Наличие этого маршрута и точный DTO необходимо подтвердить у backend-разработчика: этот endpoint не был описан в переданном контракте. Если сервер использует другой URL или набор полей, измените `AuthEndpoints.UPDATE_CURRENT_USER` и JSON в `AuthApi.updateCurrentUserProfile`.

## Каталог тренировок

Пока backend не предоставил API каталога, используются четыре явно демонстрационные записи — ровно по одной на категорию. Время и описание являются примерными; калории и SportCoins равны нулю, потому что достоверные значения не заданы. Для перехода на БД нужно заменить `demoWorkoutExercises()` вызовом согласованного workout endpoint.

## Сборка

Откройте папку проекта в Android Studio, используйте JDK 17, выполните Gradle Sync и затем **Build → Rebuild Project**. В конфигурации: Android Gradle Plugin 8.1.1, Gradle 8.0, Kotlin 1.9.0, Compose Compiler 1.5.1, compile/target SDK 34 и min SDK 24.

## Серверный контракт

Путь и DTO подтверждения регистрации (`/api/auth/email-confirm`, `emailCode`) соответствуют обновлению от 02.11. Маршруты восстановления пароля, refresh и logout собраны в `AuthEndpoints`; их точные URL/DTO необходимо подтвердить с backend-разработчиком, поскольку полный серверный контракт этих операций не присутствует в исходном архиве. См. `README_SERVER_API_RU.md`.
