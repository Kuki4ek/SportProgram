# Обновление SportakusAuth V2.0.14-light — backend API от 18.11

## 1. Профиль пользователя

Подключён новый частичный контракт `PUT /api/users/me` с JWT. Клиент формирует JSON только из изменённых непустых полей:

- `newLogin`;
- `newNickname`;
- `newEmail` и `emailCode` (только после отдельного подтверждения);
- `newPhone`;
- `newPassword`;
- `weight` и `height` как целые числа.

Неизменённые поля не отправляются. Пустые поля не отправляются, поскольку backend их игнорирует.

Перед изменением электронной почты приложение вызывает `POST /api/users/me/email-confirm` с `newEmail`, после чего пользователь вводит полученный код. Код передаётся в `PUT /api/users/me` вместе с `newEmail`.

Поле «Полное имя» оставлено локальным в SharedPreferences: в спецификации от 18.11 backend-поля для полного имени нет. Серверные поля, перечисленные в спецификации, редактируются через API.

## 2. Партнёры

Добавлен раздел «Партнёры»:

- `GET /api/partners` — список партнёров для авторизованного пользователя;
- `GET /api/partners/{id}` — карточка выбранного партнёра;
- `POST /api/partners` — создание (только роль `ADMIN`);
- `PUT /api/partners/{id}` — полная замена полей партнёра (только `ADMIN`);
- `DELETE /api/partners/{id}` — удаление (только `ADMIN`).

Клиент скрывает административные элементы для пользователей без роли `ADMIN`; сервер остаётся окончательной точкой проверки прав и может вернуть `403 Forbidden`.

## 3. Обработка ошибок

Добавлена обработка `application/problem+json`. При `400 Bad Request` приложение извлекает массивы сообщений из `errors`, включая ключи `NewLogin`, `NewNickname`, `NewEmail`, `NewPhone`, `NewPassword`, `Weight`, `Height` и `email`. Исходное написание ключей сохраняется в модели ошибок. Для `403` и `404` выводятся понятные сообщения.

Новые защищённые запросы выполняются через общий механизм авторизации: при `401` выполняется `/api/auth/refresh`, после чего исходный запрос повторяется один раз. Обновлённые JWT и refresh-токен сохраняются.

## 4. Важные границы контракта

- Все перечисленные новые endpoints вызываются с `Authorization: Bearer {jwt}`.
- Для email-confirm нужен `newEmail`; подтверждение почты завершается только после ввода кода и успешного `PUT /api/users/me`.
- Partner-объект использует поля `id`, `name`, `logo`, `contactName`, `contactEmail`, `contactPhone`.
- Полное имя не отправляется на backend до появления соответствующего поля в API; оно остаётся локальным.

## Проверка

`AuthApi.kt` отдельно проверен компилятором Kotlin 1.9.0 с заглушками `org.json`: ошибок компиляции API-слоя нет. Полную Android/Compose-сборку выполнить не удалось: Gradle Wrapper не смог скачать Gradle 8.0 из `services.gradle.org` из-за недоступности хоста в среде проверки. Перед выпуском APK требуется выполнить Gradle Sync и `Build > Rebuild Project` в Android Studio.
