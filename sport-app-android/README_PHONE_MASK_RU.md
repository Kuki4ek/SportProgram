# Автоматический международный номер телефона — SportakusAuth 1.20

## Поведение поля

Пока пустое поле телефона не выбрано, в нём отображается обычная подсказка («Номер телефона» или подпись конкретного поля). Когда пользователь нажимает на пустое поле, подсказка сменяется на автоматически появившийся знак `+`. Сам знак не нужно вводить с клавиатуры — пользователь набирает только цифры, начиная с международного кода страны.

Форматирование применяется по мере набора и учитывает распознанный код страны. Например, номера разных стран оформляются по правилам соответствующего телефонного плана, а не по фиксированной маске `+7 (XXX) XXX-XX-XX`. Используется Google libphonenumber (`com.googlecode.libphonenumber:libphonenumber:9.0.41`).

Внутреннее состояние полей содержит только цифры. Знак `+`, пробелы, скобки и дефисы добавляются только визуальным преобразованием, поэтому символы форматирования не попадают в редактируемое значение и не отправляются на сервер как часть номера.

## Где работает

- необязательный номер телефона при регистрации;
- номер телефона при восстановлении пароля;
- поле телефона при подтверждении регистрационного контакта;
- переиспользуемое поле контакта, где пользователь выбирает между почтой и телефоном.

Универсальное поле входа «логин, почта или телефон» осталось универсальным: маска не вмешивается во ввод логина и адреса почты. При отправке телефонного идентификатора приложение пытается привести номер к формату E.164.

## Валидация и API

- пустой телефон при регистрации допустим, так как это необязательное поле;
- если номер указан, его нужно вводить вместе с кодом страны;
- приложение проверяет номер через libphonenumber и не привязывает валидацию к российскому коду `+7`;
- интерфейс принимает международный код страны и проверяет номер через libphonenumber;
- при регистрации номер с кодом `+7` отправляется в формате `+7 (999) 999-99-99`, как требует последняя спецификация backend-разработчика;
- для других стран отправляется формат, возвращаемый libphonenumber. Нужно убедиться, что сервер принимает международные номера, а не только `+7`;
- при отправке номера для входа приложение по-прежнему нормализует его в E.164 (например `+358401234567`);
- при вставке номера вместе с пробелами, скобками или дефисами в состояние сохраняются только цифры.

## Регистрация с подтверждением почты

Сначала отправляется `POST /api/auth/request-email-confirm` с `login` и `email`. Только после ввода кода вызывается `POST /api/auth/register` с полями `login`, `email`, `code`, `password` и необязательным `phone`. Подробности и примеры см. в `README_EMAIL_CONFIRM_FLOW_RU.md`.

## JSON входа

Клиент анализирует то, что пользователь ввёл в одно поле «Логин, почта или телефон», и отправляет одно соответствующее свойство вместе с паролем.

Вход по логину:

```json
{
  "login": "Alice",
  "password": "veryStrongPassword123"
}
```

Вход по почте:

```json
{
  "email": "example@example.com",
  "password": "veryStrongPassword123"
}
```

Вход по телефону:

```json
{
  "phone": "+358401234567",
  "password": "veryStrongPassword123"
}
```

Клиент определяет почту по наличию `@`, телефон — по `+` или числовому формату, в остальных случаях отправляет `login`. Успешный ответ входа должен содержать `jwt`.

## Примечание о сервере

Сервер должен сохранять и сравнивать телефон в одном каноническом формате (предпочтительно E.164, например `+358401234567`). Если существующие записи в базе уже сохранены в формате `+7 (XXX) XXX-XX-XX`, их потребуется нормализовать либо учесть старый формат на стороне API.
