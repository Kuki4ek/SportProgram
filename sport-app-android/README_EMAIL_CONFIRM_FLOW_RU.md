# Подтверждение почты перед регистрацией

Описание текущего потока подтверждения почты в Android V2.

## Последовательность запросов

1. На форме регистрации локально проверяются login, email, телефон (если заполнен) и пароль.
2. Клиент выполняет `POST /api/auth/email-confirm` с JSON, содержащим только `login` и `email`.
3. После HTTP-успеха открывается уже существующий экран ввода кода. Письмо отправляет сервер; код и пароль не сохраняются на сервере через этот первый запрос.
4. При повторной отправке кода клиент снова вызывает `/api/auth/email-confirm`.
5. После ввода шести цифр клиент выполняет `POST /api/auth/register` с `login`, `email`, `emailCode`, `password` и необязательным `phone`.
6. JWT сохраняется и приложение переходит к странице API-профиля только после успешного ответа регистрации.

## Формат телефона

Российские номера отправляются в формате `+7 (999) 999-99-99`, как указано в контракте. Для других стран сохраняется форматирование libphonenumber, поскольку интерфейс по требованию пользователя не ограничивает код страны значением `+7`. Backend-разработчик должен подтвердить, что его валидатор принимает такие номера; если сервер намеренно принимает только `+7`, требования к UI и API нужно согласовать.

## Поведение при ошибках

- Если запрос кода не прошёл, пользователь остаётся на форме регистрации.
- Если регистрация с кодом не прошла, пользователь остаётся на экране ввода кода и видит сообщение API.
- Кнопки подтверждения и повторной отправки отключаются на время соответствующего запроса.
- Повторная отправка вызывает серверный endpoint, а не только перезапускает таймер.

Полная сборка зависит от доступности Gradle и окружения Android SDK; проверка исходников и архива не заменяет Build/Rebuild и прогон на эмуляторе.
