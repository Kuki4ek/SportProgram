# Спортакус — Android-клиент

Учебное Android-приложение на Kotlin и Jetpack Compose со светлой и тёмной темами, анкетой и экраном тестирования API.

## Запуск

1. Распакуйте архив в отдельную папку.
2. В Android Studio выберите **File → Open** и откройте папку с `settings.gradle.kts`.
3. Дождитесь Gradle Sync.
4. Выполните **Build → Rebuild Project**, затем нажмите **Run ▶**.

## Тестовый API

Приложение поддерживает редактирование базового URL сервера через кнопку **«Адрес сервера»** на стартовом экране. Адрес сохраняется между запусками.

Подключены:

- запрос кода подтверждения почты: `POST /api/auth/request-email-confirm`;
- регистрация после ввода кода: `POST /api/auth/register`;
- вход: `POST /api/auth/login`;
- получение текущего пользователя: `GET /api/users/me` с заголовком `Authorization: Bearer <jwt>`.

ПРИМЕЧАНИЕ: последняя спецификация, присланная разработчиком, повторяет `/api/auth/register` в заголовке раздела «Вход». В коде используется `/api/auth/login`, поскольку этот маршрут был указан в более раннем контракте. Перед демонстрацией подтвердите маршрут с backend-разработчиком.

При регистрации приложение сначала запрашивает код по почте, а затем отправляет все регистрационные данные вместе с кодом. После успешной регистрации или входа приложение сохраняет JWT в `TokenStore` и открывает тестовую страницу. Она делает `GET /api/users/me` и выводит `Привет, <login>` по полю `login` ответа сервера.

Подробная инструкция: `README_SERVER_API_RU.md`.

## Адрес сервера

- Android Emulator, сервер на том же компьютере: обычно `http://10.0.2.2:5000`.
- Физический телефон в той же сети: IP компьютера и порт API.
- Между разными сетями: публичный HTTPS URL или туннель; внутренние адреса `localhost`/`10.0.2.2` не работают.

## Ограничения тестовой версии

JWT хранится в `SharedPreferences` как временное учебное решение. Для production нужны HTTPS и защищённое хранилище. OAuth Google/Яндекс, восстановление пароля и refresh-токены пока не подключены. Полную сборку нужно проверить в Android Studio.


## Светлая и тёмная темы

В этой версии доступны обе темы. На экране выбора способа входа (экран «Спортакус — двигайся и зарабатывай») нажми на значок солнца/луны в левом верхнем углу. Переключатель есть только на этом экране, но выбранная тема применяется ко всему приложению — заставке после перехода, анкете, входу, регистрации, настройке сервера и тестовой странице профиля. Выбор сохраняется между запусками. По умолчанию используется тёмная тема, так как это текущий основной вариант оформления.

Цветовые функции используют единый источник — `MaterialTheme.colorScheme`: `onSurface` для основного текста, `onSurfaceVariant` для вторичного текста, `surfaceVariant` для полей, `primaryContainer`/`onPrimaryContainer` для выбранных вариантов и `onPrimary` для текста на основных кнопках. Отдельный `LocalSportakusDarkMode` для вычисления цветов удалён.

## Исправление цветов (1.17)

- Основной текст, вводимый текст, фон полей и выбранные пункты связаны с ролями одной активной цветовой схемы.
- Убраны проверки `sportakusIsDarkTheme()` из логики выбора цветов. Переключатели используют согласованную пару `primaryContainer`/`onPrimaryContainer`.
- Палитры светлой и тёмной темы сохранены: в светлой теме основной текст чёрный и поля белые; в тёмной теме текст светлый, а поля тёмные.
- Версия приложения: `1.17-scheme-color-source` (`versionCode = 18`).

ZIP проверен на целостность. Перед демонстрацией обязательно выполните **Build → Rebuild Project** и визуально проверьте ввод, скроллы и выбранные варианты в Android Studio на обеих темах.


## Международный ввод телефона (1.19)

- До нажатия на пустое поле показывается обычная подсказка «Номер телефона». После фокусировки автоматически появляется `+`; пользователь вводит только цифры, начиная с кода страны.
- Форматирование определяется распознанным международным кодом страны через libphonenumber; фиксированный `+7` не навязывается.
- Для регистрации российский номер преобразуется к формату `+7 (999) 999-99-99`, указанному backend-разработчиком; для других стран сохраняется распознанный международный формат. Уточните на сервере, принимает ли его валидатор для международных номеров.

## Подтверждение почты и регистрация (1.20)

1. Пользователь заполняет имя, почту, необязательный телефон и пароль. Данные остаются в состоянии приложения; запрос регистрации ещё не отправляется.
2. Приложение вызывает `POST /api/auth/request-email-confirm` с JSON `{ "login": "Alice", "email": "example@example.com" }`.
3. После успешного ответа показывается существующий экран ввода шестизначного кода. Повторная отправка вызывает тот же endpoint.
4. После нажатия «Подтвердить» приложение вызывает `POST /api/auth/register` с `login`, `email`, `password`, `code` и необязательным `phone`.
5. JWT сохраняется только после успешной регистрации; при ошибке пользователь остаётся на экране кода.

Версия приложения: `1.20-email-confirmation` (`versionCode = 21`).
