# Подключение SportakusAuth к тестовому C# API

## Что подключено

- `POST /api/auth/request-email-confirm` — запрос кода подтверждения электронной почты;
- `POST /api/auth/register` — создание аккаунта после передачи кода;
- `POST /api/auth/login` — вход по логину, почте или телефону;
- `GET /api/users/me` — получение текущего пользователя с JWT;
- настройка базового URL сервера прямо из приложения;
- сохранение JWT после успешного входа или регистрации;
- отображение серверных, сетевых и полевых ошибок.

## Регистрация с подтверждением почты

Кнопка «Регистрация» сначала проверяет введённые данные локально, а затем отправляет только имя и email:

```json
{
  "login": "Alice",
  "email": "example@example.com"
}
```

Endpoint: `POST {baseUrl}/api/auth/request-email-confirm`.

После успешного ответа показывается экран ввода шестизначного кода. Нажатие «Повторить» вызывает этот же endpoint снова. Пока код не введён, `POST /api/auth/register` не вызывается.

После подтверждения клиент отправляет:

```json
{
  "login": "Alice",
  "email": "example@example.com",
  "code": "123456",
  "password": "veryStrongPassword123",
  "phone": "+7 (999) 999-99-99"
}
```

Свойство `phone` необязательное и опускается, если телефон не заполнен. Для российских номеров клиент формирует указанный backend-разработчиком формат `+7 (999) 999-99-99`. При этом интерфейс всё ещё поддерживает ввод международного номера с разными кодами стран; сейчас для не-российских номеров отправляется формат, который выдаёт libphonenumber. Нужно подтвердить с backend-разработчиком, принимает ли сервер международные номера или его валидатор строго ограничен форматом `+7`.

Для пароля в регистрации клиент требует более 8 символов. При успешной регистрации клиент ищет токен в JSON-полях `jwt`, `JWT`, `access_token`, `accessToken` либо в заголовке `Authorization: Bearer ...`.

## Важно: путь входа

В одной из предыдущих инструкций в разделе «Вход» повторно указывался `POST /api/auth/register`. Это похоже на опечатку, потому что ранее backend-разработчик указывал `POST /api/auth/login` для входа. Android-клиент вызывает `POST {baseUrl}/api/auth/login`. Перед тестированием подтвердите маршрут с разработчиком.

## JSON входа

Клиент анализирует то, что пользователь ввёл в одно поле «Логин, почта или телефон», и отправляет одно соответствующее свойство вместе с паролем.

Вход по логину:

```json
{
  "login": "Alice",
  "password": "veryStrongPassword123"
}
```

Вход по почте:

```json
{
  "email": "example@example.com",
  "password": "veryStrongPassword123"
}
```

Вход по телефону:

```json
{
  "phone": "+358401234567",
  "password": "veryStrongPassword123"
}
```

Клиент определяет почту по наличию `@`, телефон — по `+` или числовому формату телефона, в остальных случаях отправляет `login`.

Успешный ответ входа также должен содержать `jwt`.

## GET /api/users/me

После входа/регистрации токен сохраняется локально. При запросе профиля приложение отправляет:

```http
GET {baseUrl}/api/users/me
Authorization: Bearer <jwt>
Accept: application/json
```

Клиент ожидает JSON такого вида:

```json
{
  "login": "Alice",
  "phone": "+358401234567",
  "email": "example@example.com",
  "createdAt": "2026-10-20T22:16:15.27983Z",
  "balance": 0,
  "daysStraight": 0
}
```

Для приветствия используется поле `login`, поэтому экран покажет `Привет, Alice`.

## Настройка адреса сервера

На стартовом экране нажми «Адрес сервера» и введи только базовый URL, без `/api/...` в конце.

- Android Emulator и сервер на том же компьютере: обычно `http://10.0.2.2:5000`.
- Физический телефон в той же Wi-Fi сети: `http://<LAN-IP-компьютера>:<порт>`.
- Телефон в другой сети: нужен публичный HTTPS URL или временный HTTPS-туннель; `localhost` и `10.0.2.2` для этого не подходят.

ASP.NET Core должен принимать подключения на соответствующем интерфейсе, а firewall — разрешать соединение. Убедитесь, что URL совпадает с фактическим портом `launchSettings.json` или настройкой запуска.

## Статус

Тестовая сборка использует `HttpURLConnection`, `org.json.JSONObject`, Kotlin coroutines и `Dispatchers.IO`; дополнительная HTTP-библиотека не нужна. JWT сохраняется в `SharedPreferences` как временное решение для учебной демонстрации. Перед production нужен HTTPS и защищённое хранение токена.

В этой версии не подключены OAuth Google/Яндекс, восстановление пароля и обновление/refresh JWT. Они потребуют дополнительных endpoints и согласования контрактов.
